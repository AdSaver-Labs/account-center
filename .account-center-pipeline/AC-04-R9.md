# AC-04-R9 — Reauth completion evidence boundary

State: REVIEWED
Parent: AC-04-R8 / AC-04-R1; all merged candidates, including AC-06 owned-delete receipt work, are preserved.
Owner: Account Center production coordinator

## Bounded blocker-resolution plan

1. Inspect only the unused bounded reauth-proof contract and its public exports; do not touch runtime adapters, account stores, or the owned delete helper.
2. Add a pure, fixture-only reauth completion-evidence boundary that permits a terminal `VERIFIED` readiness result only for the existing exact fresh proof bound to a pending `reauth` challenge.
3. Make every missing, malformed, stale, terminal, or mismatched proof return a fixed target-free `UNPROVEN` result. It must not claim a login, credential write, route change, durable terminal challenge state, or native apply.
4. Add focused adversarial fixtures, including output serialization checks, then run full QA/security and preservation review.
5. Do not execute the owned helper, Dexter/Hermes commands, a live deletion, provider request, interactive login, credential/store write, route mutation, or service operation.

## Acceptance evidence

- Completion readiness distinguishes only fixture proof verification from native mutation; it cannot be mistaken for applied reauthentication.
- Public outcomes contain no target, credential, raw proof, request digest, or adapter diagnostic.
- Existing owned exact-account delete integration retains its single opaque receipt contract and Hermes fixture coverage; Sentinel `/auth` and Hermes/Dexter weekly-only policy stay unchanged.

## Review results

- Spec: passed — the export is a pure proof-to-readiness boundary. `VERIFIED` explicitly means only that a future native transaction is required; it cannot represent applied reauthentication.
- Quality: passed — malformed, stale, mismatched, credential-bearing, inherited, and throwing fixture proof inputs all reduce to the identical target-free `UNPROVEN` output. No runtime adapter or mutation store is imported.
- QA: passed — `npm run qa` and `npm run qa:security` passed: 259 Node fixture/mock tests, 18 Hermes plugin tests, typecheck/build, 15 Chromium/axe tests, a 142-file secret scan, and `npm audit --audit-level=high` with zero vulnerabilities.
- Preservation: the existing fixture suite passed for the owned `codex-auth-delete.py` adapter path, one opaque delete receipt, Dexter/Hermes ChatOps parity, normal Sentinel `/auth`, and weekly-only capacity policy. The helper was not executed.

No live deletion, provider request, interactive login, credential/store write, route mutation, session/service operation, or native helper execution occurred.
